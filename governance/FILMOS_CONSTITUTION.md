# FilmOS Constitution

Version: `1.1.0`

This constitution governs FilmOS product development. It is Developer Governance, not Film Core creative data. Every IssueSession, ConsensusRecord, task package, ReviewCandidate, and PilotRelease must bind the matching version and machine content hash from `FILMOS_CONSTITUTION.json`.

1. `C-01` FilmOS starts with script creation and refinement, not only storyboards.
2. `C-02` Projects and content units remain visually manageable.
3. `C-03` Every ContentUnit can open its own infinite canvas.
4. `C-04` Canvas, director controls, and production workflows remain integrated.
5. `C-05` Local-first is the default; remote mode is explicit.
6. `C-06` AI Brains are replaceable; FilmOS is their eyes and hands.
7. `C-07` AI Brains and Generation Engines are separate domains.
8. `C-08` Characters, wardrobe, scenes, architecture, style, space, and model versions can be locked.
9. `C-09` Generation passes Route, Receipt, Candidate, QC, and Approved boundaries.
10. `C-10` FilmOS permits no second data authority, Candidate authority, or Tool Broker.
11. `C-11` Paid, upload, external-project, and irreversible actions require human confirmation.
12. `C-12` Preserve Yingce upstream mergeability through adapters and extensions.
13. `C-13` Real use takes priority over abstract feature accumulation.
14. `C-14` Codex and ChatGPT jointly maintain FilmOS with distinct responsibilities.
15. `C-15` Small reversible issues use Fast Lane; core issues require consensus; architecture changes use formal evolution.
16. `C-16` Users decide product trade-offs and authorize high-risk actions; they do not shuttle engineering evidence.

## Amendment boundary

This file and the JSON contract cannot be changed as an incidental implementation edit. A change requires an `ArchitectureEvolutionSession`, Requirement Delta, independent Codex and ChatGPT assessments, an options matrix, owner decision when needed, migration and rollback plans, a Pilot, and a Constitution Migration Receipt.
