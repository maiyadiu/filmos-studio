# FilmOS 验收入口

`acceptance/合同.json` 是 RC 必验面，`FilmOS_Acceptance_Project/项目.json` 是固定验收项目定义。两者只定义范围，不充当通过证据。

当前阶段重放：

```bash
python3 acceptance/run.py --suite current
python3 acceptance/verify.py acceptance/evidence/runs/<run-id>/receipt.json
```

全量本地 RC 重放：

```bash
python3 acceptance/run.py --suite rc-local
```

每次运行创建新的 `receipt.json` 和逐项日志，记录 Commit、工作树、命令、退出码、耗时、文件大小和 SHA-256。`README`/本文件不属于验收证据。

报告从已验证 receipt 生成并反向校验：

```bash
python3 acceptance/generate_reports.py acceptance/evidence/runs/<run-id>/receipt.json
python3 acceptance/checks/reports.py
```

`acceptance/reports/REPORT_INDEX.json` 记录每份报告、原始来源和 receipt 的 SHA-256。报告是证据视图，逐项 log 和 receipt 才是权威运行证据。

`rc-local` 不包含需外部账号、真实 Provider 或额度的动作。最终 `rc-final` 会在专用凭据与输出 hash 合同接入后开放；在此之前不得创建 `filmos-v1.0.0-rc1` Tag。

固定 Local-first 全链可独立重放：

```bash
python3 acceptance/checks/full_chain.py
```

该检查在同一个真实 Film Core Sidecar 内跑通 `Project→ContentUnit→Script→Scene→DirectorUnit→Shot→Asset→SceneTwin→Prompt→Provider→Candidate→QC→Approved`，并证明精准 STALE、人类审批边界与重启一致。其 Provider 边界是 `LOCAL_MANUAL_CANDIDATE_IMPORT`，因此不得把该通过项写成“真实 CLI 生成已通过”。

唯一正式远程验收仓库合同可独立重放：

```bash
python3 acceptance/checks/remote_contract.py
```

`acceptance/MANIFEST.json` 只保存稳定验收合同：验收规范、Evidence Index、Golden Project、Yingce upstream 和 Film Core/Canvas/MCP Schema 的版本与哈希。`acceptance/EVIDENCE_INDEX.json` 也是稳定合同，只保存 Track 对应的 source、test、Golden 与 required checks，不记录候选 Commit、receipt、运行日志或通过状态。两者都不声称 Pre-RC/RC 已推送。正式外部验收唯一允许的仓库为 `maiyadiu/filmos-studio`。

候选 Commit 固定后，`acceptance/run_all` 会在 Git 忽略的 artifact 目录生成 `RELEASE_MANIFEST.json`，记录 repository、Commit SHA、Tree SHA、Acceptance Manifest Hash、Evidence Index Hash、Receipt Hash、Build ID 和 UTC 时间戳。该文件只作为 CI/Release Artifact，不回写、不提交到同一 Commit。

干净全量重放默认将原始 log、receipt 与 Release Manifest 写入 `.local/acceptance-artifacts/`；CI 上传整个目录。Runner 不回写 Evidence Index；候选 Commit、逐项结果和运行日志只由 artifact-only `RELEASE_MANIFEST.json` 与 `receipt.json` 绑定。

桌面备份/恢复 Golden 可独立重放：

```bash
python3 acceptance/checks/desktop_backup_restore.py
```

该检查实际启动两次临时本地后端，完成项目写入、`.filmosbackup` 导出、逐文件 SHA-256 校验、凭据排除、新目录恢复和重启读回。运行中间文件不进入验收包，日志由 runner 脱敏后哈希登记。
