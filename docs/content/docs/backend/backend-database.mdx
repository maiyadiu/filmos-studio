# 后端数据库

后端通过 GORM 管理 SQLite 与 PostgreSQL 表结构。服务启动时由 `backend/internal/database/schema.go` 执行迁移；业务写路径必须通过 service 和 repository 的状态约束，不能直接依赖前端状态。

## 章节正文与修订历史

本机新作品另有`project_directories`关联表：project_id主键，user_id/request_id联合唯一，request_hash、root_path、state及创建/更新时间。它只记录目录归属与同步恢复状态，不存第二份可编辑正文；旧Project没有该行，不自动迁移。状态为initializing、pending、ready、sync_failed。默认父目录在既有system_settings中按用户保存；真实路径不加入公共Project JSON。

本机新增接口：`GET /api/project-locations`，`POST /api/project-locations/choose`，`PUT /api/project-locations/default`；`GET /api/projects/:id/directory`及`POST /api/projects/:id/directory/{open,sync,relocate,export}`。本机创建项目增加`localDirectory:{requestId,locationToken?}`；公开部署禁止该字段。写路径要求回环真实对端、合法本机Host、精确同源或显式开发Origin，以及`X-FilmOS-Project-Directory: 1`和JSON内容类型。

目录同步不与数据库伪装成单个原子事务。业务写前检查已关联目录，写后投影实际提交状态；失败保留数据库和现场并返回错误，状态供重试同步回读。共享素材影响所有已关联作品，画布改绑同步旧/新项目。目录模板、资源引用与用户恢复说明见[作品目录](../overview/作品目录.mdx)。

### 正文与修订

本机目录同步同时输出批次回执为`历史/建章-<批次ID>.json`，与正文和逐版历史一起进入既有内容包；文件是可核对的投影，不作为另一个可编辑库或自动恢复入口。

从零编剧新增 `project_script_batches`：项目/request_id联合唯一，保存请求哈希、创建后项目版本、章节ID列表、创建者与时间；不复制可编辑正文。`POST /api/projects/:id/script-batches` 接收 `expectedProjectRevision/requestId/note/chapters[{title,sourceText}]`，一次1–50章、整批正文最多2MiB。项目版本CAS、章节、初稿v1历史与批次回执同事务保存；同请求重放不覆盖后续修订，异内容复用ID或陈旧项目版本返回409。`GET /api/projects/:id/script-batches/:requestId`只读原批次及v1历史，当前正文须另读章节；已删章节不能借原请求重建。回执随项目删除清理，均检查登录及项目归属。关联本机目录仍沿用业务写前检查/写后同步，不宣称数据库与文件系统是原子事务。

`project_units.source_text` 仍是章节编辑器的当前正文（HTML）；`revision` 为非空整数，新增及迁移前的章节从 1 开始。`project_unit_revisions` 在同一业务数据库保存追加式修订：项目/章节 ID、修订号、标题、完整正文、SHA-256、章节状态、请求 ID/请求哈希、说明、操作用户和时间。首次修改会同时保存修改前的原始版本；历史记录不被后续编辑覆盖，随所属章节/项目的既有删除事务清理。

`project_units.chapter_canvas_id` 是章节唯一默认画布的可空身份引用（API 为 `chapterCanvasId`），唯一索引 `idx_project_units_chapter_canvas` 防同一画布成为多章主画布。现有章节迁移时保持 NULL，不猜历史主画布、不改正文及修订号。普通章节取得/创建接口在项目行写锁事务内保存画布、原 `canvas_unit_links` 和该引用；只有单一历史关联时自动复用，多个历史关联返回待选择，所有旧内容保留。引用确立后通用解绑、跨项目改挂和批量同步不能替换它；显式删除原画布时同事务清空引用，之后允许新建。此字段不代表正式 Production Canvas 批准，也不取代其审计守卫。

登录态 `POST /api/projects/:id/units/:unitId/chapter-canvas` 接受 `{}`，或历史选择用 `{ "canvasId": "候选ID" }`；返回 `disposition` 为 `created`、`adopted`、`reused` 时包含 `canvas` 摘要，`selection_required` 时仅包含 `candidates`，不创建画布。已有唯一绑定不能改选；同画布跨章主绑定、跨项目改挂等冲突返回409；归属不匹配返回404。普通创建遵守原存储配额，归档项目不新增/指定绑定。浏览器按回执 ID 回读单画布及章节身份，只接入该画布；不替换其他画布，不覆盖本地草稿或推进其旧 CAS 基线。导入业务分镜仍走既有版本校验、保存及回读，不重新分镜或调用模型。

- `GET /api/projects/:id/units/:unitId/script-revisions`：最近 50 个修订元数据，不携带正文；更早版本仍可按修订号读取。
- `GET /api/projects/:id/units/:unitId/script-revisions/:revision`：精确版本正文及哈希；未修改章节返回当前初始版本，不因读取写库。
- `POST /api/projects/:id/units/:unitId/script-revisions`：Agent 草稿修订，仅允许 draft/ready，不更改完成/审批状态。
- 原 `PATCH /api/projects/:id/units/:unitId` 编辑器保存使用同一事务。两种写入都要求 `expectedRevision`、唯一 `requestId` 与 `sourceText`，可携带标题和说明。旧调用方不能省略版本守卫。

所有读取/写入经登录态与项目归属检查。CAS 更新当前正文、保存前后版本、递增项目版本在同一事务完成；失败整体回滚。相同请求 ID 与相同请求内容重发复用原结果，内容不同或基线过期返回 HTTP 409 和非零业务错误码。正文限 2 MiB。SQLite 同时抢占写锁也可能返回数据库忙，此时不能当作保存成功，应先回读。

这是日常章节编辑历史，不是 Film Core 的正式 `ScriptVersion` 审阅/批准/锁定，也不生成 Candidate、Consensus 或图片。Agent 工具成功后再次读取精确修订和当前章节，比对项目、版本、正文与哈希；保存响应和回读不一致时不报告完成。

## 业务分镜与批次回执

`shots` 继续作为业务镜头的唯一权威，画布 `project-shot:<id>` 是展示映射。新增 `revision`（旧镜头迁移为1）、`source_revision`（未绑定为0）、`source_hash` 与 JSON `content`；后者保存来源段落引用、场景、角色名、精确对白、动作和镜头要求。旧镜头内容与ID不变，不凭空补来源；当前脚本版本或哈希不同的镜头标记过期。段落ID只在指定章节、脚本修订号和哈希内有效，不是跨版本不变的场景ID。

- `project_units.shot_revision`：章节分镜集合版本，初始0；批量与普通单镜头写入都递增，用于冲突检测。
- `shot_revisions`：同库追加镜头快照、修订号、内容SHA-256、请求/操作者/时间；已有镜头首次修改补存原版本。
- `shot_batch_receipts`：同库保存章节/requestId唯一键、请求哈希、脚本来源、`source_paragraph_ids`编辑范围、集合版本及本批镜头快照。相同请求重发返回原回执；不同内容复用requestId返回409。

接口均检查登录与项目归属：

- `GET /api/projects/:id/units/:unitId/shots`：完整来源正文、版本/哈希、段落及可识别的`dialogue`、当前镜头、过期镜头ID和`coverage`。
- `PUT /api/projects/:id/units/:unitId/shots`：要求requestId、expectedShotRevision、sourceRevision/sourceHash、sourceParagraphIds和1–100个结构化镜头，正文上限2 MiB。修改必须给原镜头id/expectedRevision；新镜头不传id且expectedRevision=0。**不再删除或全章替换**，未传镜头及原素材引用/候选保持不变。
- `GET /api/projects/:id/units/:unitId/shot-batches/:requestId`：精确批次回执，供丢失响应后恢复，不代表当前版本。
- `GET /api/projects/:id/shots/:shotId/revisions`：镜头修订历史。
- 原 `POST /api/projects/:id/shots`：同一事务版本路径，修改要求expectedRevision；保留已有结构化内容和脚本来源，不允许靠省略unitId移动镜头。

整批先校验来源、条目及归属，再以章节来源/集合版本CAS提交；镜头、历史、回执、项目版本任一失败全部回滚。同章节位置不可重复，批次不改变已完成章节或镜头。回执从事务内实际落库行生成，包含数据库处理后的时间精度，不能用内存拟写对象冒充已存版本。普通手工写入亦守护章节状态与集合版本。项目/章节删除沿既有事务清理所属历史和回执。

`sourceParagraphIds`明确本批编辑覆盖范围：全章任务传全部段落，局部任务不能缩小原镜头已覆盖的范围来丢失对白。引用合并须完整覆盖范围内原文，结构化对白的说话人、文字（含空白）、顺序须完全一致；允许一句对白跨连续镜头分配，不要求逐句切镜。与未修改的新鲜镜头合并核验，禁止颠倒相邻原对白。解析保留原文用于引用，排除场景/动作等已知标签并支持说话人的括注及外层Markdown格式；不是任意格式的通用剧本解析器。`coverage.chapterComplete`仅表示原文引用与已识别对白覆盖，不证明动作可见性、空间因果或导演质量。前端详细对白对照复用既有保真比较；规模超过阈值时仅跳过高开销细节比较，不截断原文或绕过后端保存验证。

Agent保存后经共享API回读批次与当前镜头，逐字段比较来源、ID、版本及内容；若后来已有修改，回传`persisted=true, matchesCurrent=false`，不宣称旧请求是当前验收结果。网络失败不能改用新requestId盲建镜头。本合同不自动批准/锁定Film Core对象，不生成图片；完整对白/场景覆盖和真实创作质量单独验收，基础来源引用校验不等于语义完整性证明。

## 单画布同步版本

原 `GET /api/canvas-projects/:id` 返回 `project` 和服务端持久 JSON 的 `contentHash`；聚合 `GET /api/user-data/snapshot` 同时返回 `projectContentHashes`，不额外逐条读取。原 `PUT /api/canvas-projects/:id` 接受可选 `expectedContentHash`：非空必须匹配当前内容，空串仅允许创建不存在的画布；缺失沿用原调用合同。成功摘要返回实际保存的 `contentHash`。版本冲突是 HTTP 409 和非零业务码；不覆盖原数据。无需新增数据库字段或表。

浏览器同步必须使用服务端提供的版本，不自行推算或以空值兜底覆盖。单画布分镜同步与原生导入复用同一队列和映射，不保存其他脏画布/素材，不上传本地媒体。保存后精确回读，安全应用本地节点后才确认同步基线，防止后续自动保存撤销已保存的 Agent 结果。章节关联与画布保存是两个既有事务，回执分别标明保存、本地应用、关联、来源复核结果；部分完成不伪称整体成功，也不自动回滚覆盖。

提示词读取的 `canvasUpdatedAt` 来自该次数据库快照内的画布 JSON。提示词保存会在同一事务更新此时间；前端校验预期画布时使用该已读时间，而不是旧保存时间或浏览器本机时间，其余字段仍逐项严格比较。连续保存图像/视频草稿后，普通画布编辑继续使用最新服务端 CAS 版本。

## 日常分镜提示词（接入中）

当前正文仍在 `canvas_projects.payload_json` 的原生分镜行 `imageGenerationPrompt` / `videoMotionPrompt`，不另设可编辑的“当前提示词库”。`promptDrafts.image|video` 只记录修订号、正文 SHA-256 和依赖 SHA-256；编译回执不是保存回执，也不是生成结果或 Film Core 正式审批。

- `canvas_prompt_revisions`：同库追加画布/节点/行/类型/修订号唯一快照、完整文本、来源依赖、哈希、requestId、用户与时间。第一次保存补记原文本为 revision 0，依赖为 null，明确旧文本没有可证明的创作来源；迁移本身不改旧画布、不伪造历史。
- `canvas_prompt_receipts`：画布/requestId 唯一，保存请求哈希和已存修订快照。同请求同内容复用原回执，不同内容返回409；旧请求回执不冒充当前版本。

登录态接口（全部检查画布归属）：

- `GET /api/canvas-projects/:id/prompt-drafts?projectId=…&nodeId=…&rowId=…&kind=image|video`：同一数据库快照读取当前正文、版本、来源、过期和不可写原因。`dependencies.guidance` 复用原生首帧/视频模板与用户定制编译器；完整镜头文字不走生成侧的截短 helper。模板、定制内容及身份纳入依赖哈希，变化时旧稿过期，历史不补写。没有实际模型能力绑定时仅是创作指导，不代表模型适配完成。
- `POST /api/canvas-projects/:id/prompt-drafts`：要求上述定位、requestId、expectedRevision、expectedContentHash、dependencyHash 与 prompt。正文1–64 KiB、依赖最多1 MiB，沿用画布写限流、数据大小和存储配额校验。
- `GET …/prompt-drafts/history?nodeId=…&rowId=…&kind=…`：最近50版元数据，不加载全文；`GET …/history/:revision` 精确读取包括0版在内的已存历史。
- `GET …/prompt-drafts/requests/:requestId`：丢失响应后的原请求回读。历史读取不依赖来源素材仍然存在，避免上游删除后无法找回旧草稿。

写入在同一事务重新核验项目、章节关联、稳定业务镜头、当前脚本/镜头版本以及有效画布导演字段。原生手工机位等调整以 `localOverrides` 明示，与业务镜头并列保留，不静默改写业务事实。绑定的角色/素材版本从真实项目关联和所属用户读取；固定版本与当前主版本分别解析，资源记录校验用户和元数据。`visualVerified=false` 明确这里只证明引用/版本，未读取像素、不证明构图正确。来源或素材改变后旧草稿标记过期；过期镜头/画布映射禁止新写，已完成对象不通过此入口修改。

当前字段、追加历史和请求回执一起提交或回滚，最终画布JSON使用CAS；数据库并发忙/序列化冲突返回409，先按原requestId回读，不盲造新请求。普通整画布PUT和整批同步不得改写已有管理版本。原生删除行/节点必须携带最近一次提示词写入的 `promptWriteToken`，旧画布不能删除新稿，单独抹掉仍存在行的版本元数据也被拒绝；被删除行的历史保留。显式解除项目关联要求画布快照没有变化并保留提示词；不能直接把管理中的提示词画布改挂到另一项目。显式删除整个画布时，在原事务清理该用户该画布的提示词历史/回执，不触及其他画布。

目前已接通后端服务/API及隔离测试，原生编辑器、Agent工具与真实自然语言端到端仍在M3实施，不能把后端测试通过写成整项功能交付。PostgreSQL运行验证和完整源码CI另列后续验收，不由SQLite测试代替。

## Production Canvas

| 表 | 用途 | 关键边界 |
| --- | --- | --- |
| `canvas_projects` | Host 画布本体与画布 JSON | 画布 JSON 是交互和布局数据，不是 Film 正式空间事实 |
| `canvas_unit_links` | 关联 Host Canvas 与 ProjectUnit | `role=production` 只能经过专用 Human 确认端点创建；通用关联/解除接口拒绝该 role |
| `production_canvas_guards` | 以 Project + Unit 自然键保证唯一默认生产画布，关联 Human 确认、SourceText hash 和追加审计回执 | 只是 Host 并发/审计 companion；不保存 SceneTwin、影视状态或正文，不取代 Film Core |

正式取得/创建在同一数据库事务内重读 Project revision 与 ProjectUnit `SourceText` SHA-256，并提交 Canvas、Link、Guard、`admin_audit_events` 和新 revision。并发重放复用同一 Canvas/Link/Audit ID；重复历史关联会报出精确 Canvas ID 并停止写入。开关 `CANVAS_FILM_PRODUCTION_CANVAS_WRITE_ENABLED` 默认为 `false`。

## ComfyUI Bridge

| 表 | 用途 | 关键边界 |
| --- | --- | --- |
| `comfy_bridges` | 保存用户注册的 Bridge 身份、Token 摘要、启用状态和心跳能力 | Token 明文只在注册时返回一次；查询和日志只使用摘要 |
| `comfy_bridge_requests` | 保存云端任务交给本地 Bridge 的请求、领取状态和完成结果 | `id` 同时作为任务的 `provider_request_id`；状态按 `queued -> claimed -> succeeded/failed/cancelled` 单向流转 |

`comfy_bridge_requests` 是 Bridge 交接的真相源。后端进程重启后，未领取请求继续从数据库投递；已领取请求的迟到结果先落库，任务 worker 恢复后使用原请求 ID 读取结果，不会创建第二次本地工作流执行。请求有效期当前为两小时，过期的排队或执行记录会转为失败。

请求表保存工作流执行 payload 和结果，但不保存 Bridge Token。任务取消时，未领取请求可以确定取消；已经领取的本机工作流无法可靠中止，迟到结果会被丢弃并进入费用核对流程。
