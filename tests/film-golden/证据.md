# 第二阶段 Web / Golden A 证据

## 已验证入口

- `VITE_FILM_PRODUCTION_CORE=true` 与 `VITE_FILM_PRODUCTION_CANVAS=true` 必须同时显式成立；任一关闭时不请求 Sidecar、不产生 Film DOM。
- 只接受带显式端口的本机 HTTP Sidecar，`GET /health` 必须返回 `status=ok` 与 `service=film-production-core`；端口不可用时入口不出现。
- Project 页面复用现有 ContentUnit、CanvasUnitLink 与 Production Canvas 导航决策。唯一 `production` 关联可打开；重复关联显示全部 Canvas ID 并 fail closed；缺失关联只显示创建预演，不调用旧 storyboard 创建路径。
- 关闭、端口不可用、恢复、再次关闭均有组件级静态 DOM 测试；既有章节和 storyboard 文件未修改。

## 已验证真实 HTTP Golden A

- runner 启动真实 Film Core HTTP Sidecar，使用临时端口和临时 SQLite；退出后清理，未启动持久服务。
- Project、ContentUnit、Shot 使用 Core UUIDv4；普通 ScriptVersion 保持 unlocked，非人工锁定返回 409，人工 `/script-versions/lock` 原子创建 ScriptDecision 与新 locked ScriptVersion。
- DirectorUnit 同时绑定 locked ScriptVersion 与 ScriptDecision；CoverageLink、VisualLockSet、AssetBinding 均为正式记录。
- 真实本地 Production Canvas 投影、Prompt compiler、Manual Provider import 均参与纵向链；Core 随后持久化 PromptDraft/Provenance、GenerationPackage、AttemptEvidence 与 Candidate。
- stale VisualLock aggregate guard 编译返回 409，改用当前 version/hash 后恢复；Continuity QC 与 automated review 通过。
- 非人工 Approval 返回 409；Human Approval 是独立 UUIDv4 记录，Candidate 内容和 pending review state 未被改写。
- 全链区分 `prepared/persisted/reviewed/approved=true` 的不同证据来源；外部 Provider 调用数 0，`fallback_mock_used=false`。

## 缺 operation 时的阻断语义

runner 会先从真实 `/openapi.json` 检查八个所需 HTTP operation。任何一个缺失时回执必须为
`BLOCKED_MISSING_CORE_OPERATION`，并明确记录
`prepared/persisted/reviewed/approved=false`、`external_provider_calls=0`、
`fallback_mock_used=false`，不得降级为 Mock。本批稳定 Core 的八个 operation 均已存在，
因此完整 HTTP Golden A 已实际运行并标记 `PASSED`。
