# 使用与恢复

## 本机候选启动

所有仓库默认开关保持 `false`。隔离测试时只显式开启需要的本机能力：

```bash
npm --prefix packages/filmos-tool-contracts run build
npm --prefix services/filmos-chatgpt-app run build
FILMOS_CHATGPT_LOCAL_DIR=.local/filmos-chatgpt npm --prefix services/filmos-chatgpt-app run grant -- issue <project-id> local-desktop 15
```

原始 Project Grant token 只显示一次，应由桌面 Keychain 或当前受控进程持有。服务端文件只保存 SHA-256，不把 token 放入 URL、日志、插件或项目文件。

启动进程必须绑定 `127.0.0.1`/`::1`，并显式开启 `FILMOS_CHATGPT_APP_ENABLED`、`FILMOS_CHATGPT_READ_TOOLS_ENABLED`；需要 Widget 时再开启 `FILMOS_CHATGPT_WIDGETS_ENABLED`。Proposal 还要求 `FILMOS_CHATGPT_PROPOSAL_HANDOFF_ENABLED=true`、本机签名密钥和已配置 Python importer。

## Fail-closed 恢复顺序

1. 先将七个 `film.chatgpt_*` 和对应运行环境值恢复为 `false`，确认原影策/FilmOS 工作台仍可用。
2. 撤销当前 Project Grant；已有 MCP session 的下一次请求必须以 `GRANT_REVOKED` 失败。
3. 停止 loopback MCP 进程。不要创建公网 listener，不要用临时反向代理代替 Secure MCP Tunnel。
4. 如果 Tunnel 断线或缺少平台 tunnel id/runtime key，保留 `BLOCKED_EXTERNAL_ACCOUNT`；缺少本机 tunnel client 时保留 `BLOCKED_LOCAL_CONFIG`。两种状态的 `tunnel_started` 和 `public_listener_created` 都必须为 `false`。
5. Proposal importer 不可用时返回 `PROPOSAL_IMPORT_NOT_CONFIGURED`，不得假成功；state hash、版本、签名、过期或项目冲突时重新读取上下文并重新生成，不覆盖旧包。
6. Widget 失效时关闭 `film.chatgpt_widgets`，数据工具仍可由 `film.chatgpt_read_tools` 单独控制；不得改回手写 wildcard `postMessage` bridge。
7. Tool Contract 升级前运行冻结 v1 兼容测试。`MIGRATION_REQUIRED` 时保持旧安装关闭并生成新快照，不静默改变已安装工具的必填字段或资源 URI。

## 恢复演练

```bash
npm --prefix packages/filmos-tool-contracts test
npm --prefix services/filmos-chatgpt-app test
FILMOS_TEST_PYTHON=/path/to/film-core-venv/bin/python npm --prefix services/filmos-chatgpt-app run test:golden-real
PYTHONPATH=film-core/app python -m pytest -q film-core/app/external_brains/chatgpt/tests
npm --prefix services/filmos-chatgpt-app run doctor
```

通过标准：公开写工具为 0；跨项目、撤销 Grant、路径/密钥、Prompt Injection、脚本/下载、非法 Proposal、断线和缺配置均拒绝；Python Preview 子进程不继承父进程环境；真实 Golden 记录 `fallback_mock_used=false`、`external_calls=0`。Doctor 的外部状态仍必须是 `BLOCKED_EXTERNAL_ACCOUNT`，不能写成 ChatGPT 已连接。
