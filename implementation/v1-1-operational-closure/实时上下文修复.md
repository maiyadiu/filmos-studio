## 已确认根因

1. Web 只向 Desktop 发布项目、画布和旧式 receipt 元数据，没有发布可供 MCP 使用的完整 live context。
2. 完整上下文只在 Agent `prepare_handoff` 时手工发布；External Live Activation 直接读取时没有当前值绑定到 Project Grant 与 Tunnel challenge。
3. Installed App 的真实 Domain Project 没有幂等投影进本地 Film Core，因此 `/projects/{id}/context` 合法返回 `film_project=null`。
4. `filmos_get_blockers` 在项目投影缺失时只返回空数组和 `DERIVED_FROM_PROJECT_CONTEXT`，无法证明“无阻塞”或定位 P0。
5. Review Bus 服务端已有精确 `project_id` 隔离；仍需让只读客户端验证响应中的当前项目作用域，避免历史 Issue 被错误归入当前 Grant。

## 实施路径

1. Web 形成包含 Domain Project、ContentUnit、Canvas、Selected Node、可见节点摘要和 SHA-256 状态哈希的 live context 草稿。
2. Desktop 保留最后一份草稿；在 Project Grant、MCP 与 Tunnel challenge 就绪后自动发布，并在换 Grant/challenge 后重新绑定。
3. Desktop 仅在本地 Film Core 中幂等建立缺失的 `film_project_extension` 和当前 `content_unit_extension`，再使用 Core 返回的真实 version/hash 签发最终 receipt。
4. Blockers 返回具体 code、severity、entity、状态证据与明确的 CLEAR/BLOCKED 评估。
5. Review Bus 只读响应携带 `project_id`，ChatGPT MCP 客户端对 pending 列表和历史 Issue 详情做精确作用域复核。
