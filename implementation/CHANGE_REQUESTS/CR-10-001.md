# CR-10-001｜Provider 回执与人工导入证据投影

STATUS: `ACCEPTED_STAGE_2`

裁定：`D-0005`，采用可扩展 Provider ID 的 companion `GenerationAttemptEvidence`。

## 原因

现有共享 `GenerationPackage` 只要求 `provider_kind` 与 `input_hash`，`Candidate` 只要求输出哈希。Track 10 的本地首切片需要保留可审计的 `expected_version`、参数哈希、Provider Task/Receipt 和人工导入来源，但无权修改 `film-contracts/**`。

## 请求

请 Track 02 / Program Integrator 评估为 GenerationPackage/Candidate 增加向后可演进的证据投影，或新增共享 `GenerationAttemptEvidence`：

- `generation_attempt_id`、`expected_version`；
- `provider_id`、`provider_task_id`；
- `receipt_id`、`receipt_hash`、`receipt_captured_at`；
- `parameter_hash`、`prompt_hash`、`input_hash`；
- `manual_import_source_id`、`imported_by`、`imported_at`；
- 输出引用的 stable Film ID、content hash、MIME、bytes；
- Candidate 与 Review/Approval 保持分离，审批仍绑定 Candidate content hash。

Provider ID 不建议继续做封闭枚举；若保留 `provider_kind` 枚举，应另有可扩展 `provider_id`，避免插件 Provider 修改共享核心 schema。

## 安全边界

- 不保存原始 receipt body、密钥、Cookie、data URL、绝对文件路径或外部下载 URL。
- 正式写入必须带 stable Film ID、`expected_version` 和 content/input hash；冲突 fail closed。
- Flova 当前状态为 `UNVERIFIED_SOURCE_ABSENT`，不得因 schema 枚举存在而声明可用。

## 验证建议

- JSON Schema/OpenAPI 结构测试覆盖 required/optional、hash 格式、UUID 和未知 Provider 扩展。
- Candidate 创建测试验证不会隐式生成 Approval。
- 错误 `expected_version`、receipt/input hash 不匹配、敏感字段与路径/URL 输入均拒绝。

## 回滚

共享实现未开始；拒绝本 RFC 即无代码回滚。本轨保留私有投影，继续默认关闭。
