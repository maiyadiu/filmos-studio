# CR-07-001｜PromptDraft 血缘与执行边界

状态：`ACCEPTED_STAGE_2`
申请方：`track-prompt`
Owner：`track-film-core`
影响：`film-contracts/schemas/core.schema.json`、合同测试及生成包消费方
裁定：`D-0005`，采用 companion `PromptDraftProvenance`。

## 原因

当前 `PromptDraft` 只包含 `ref/states/director_ir_hash/visual_lock_hash/model_capability_profile/prompt_text`。首条真实链需要在进入 Provider 前证明草稿绑定了正确 Project、Shot、DirectorUnit、Host PromptTemplate、AssetVersion、VisualLock 和并发版本，并明确“编译不等于提交、生成结果只能是 Candidate”。这些事实目前不能由共享合同表达。

## 请求

请 Track 02 选择内嵌字段或 companion provenance 对象，至少覆盖：

- `expected_version`；
- Project、Shot、DirectorUnit 的 Film ref + Host refs；
- Host PromptTemplate ID、operation、version、content hash；
- AssetVersion 的 Film ref + Host refs + role + priority + content hash；
- 完整 Provider capability profile 或其稳定 ref/hash；
- provider parameters 的显式 null 语义；
- `input_hash`、`prompt_hash`、`capability_hash`；
- `submission_state=NOT_SUBMITTED`、`generated_result_state=CANDIDATE_ONLY`、Approval 为独立人工动作。

## 兼容建议

优先新增 `PromptDraftProvenance` companion schema，并由 `prompt_draft_id` 关联，以避免扩大最小 `PromptDraft` 对象；不为旧字段增加静默默认值。

## 测试

- JSON Schema 接受完整绑定，拒绝缺少 expected_version、asset hash 或 capability hash 的正式编译结果。
- 同一规范化输入得到相同 input/prompt hash。
- source/visual/asset/template 任一 hash 改变都会改变血缘或使旧草稿 stale。
- GenerationPackage 只能引用审计通过的 PromptDraft；Candidate、Review、Approval 状态转换仍由各自合同约束。

## 回滚

在 Owner 接受前，本申请不改变共享合同。若拒绝，Track 07 保留本地 companion artifact，`film.prompt_kernel=false` 时不影响 Host 流程。
