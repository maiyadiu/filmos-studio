# CR-05-001｜Production Canvas 正式关联

状态：`REQUESTED`

提出轨：`05-production-canvas`

目标 Owner：`track-film-core`、`track-project-ui`

## 现状证据

- `backend/internal/model/models_project.go` 的 `CanvasUnitLink` 唯一键为 `project_id + canvas_id + unit_id`，不能保证一个 Unit 只有一个 `role=production` 默认画布。
- `backend/internal/service/project.go#LinkCanvasUnit` 会创建或更新关联并 bump Project revision，但请求不携带 expected revision/content hash，无法拒绝基于过期 Unit 快照的正式关联。
- 当前章节入口以 `role=storyboard` 新建画布；Track 05 不应越权修改 Host 核心表、API 或 Track 03 页面。

## 请求

1. 由共享 Owner 设计幂等的“取得或创建默认 Production Canvas”写路径。
2. 在正式写入时校验 `expected_revision` 与 Unit/ScriptVersion 的 `expected_content_hash`，冲突必须显式返回，不静默覆盖。
3. 数据层保证 `project_id + unit_id + role=production` 唯一；迁移前先检测并报告重复，不自动删除。
4. Track 03 在 `film.production_canvas` 默认关闭的前提下接入导航决策，启用后复用已有画布，不重复创建。

## 验收

- 并发两次创建只返回同一 Canvas ID。
- 过期 revision/hash 不产生关联或画布事实写入。
- 重复历史数据返回冲突和精确 Canvas ID 列表。
- 关闭 feature flag 时现有章节/Storyboard 流程不变。
