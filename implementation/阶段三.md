# 第三阶段｜Golden B 与精准 STALE

## 目标

在第二阶段真实 Golden A 之上完成第 8–14 天核心生产能力的本地可重放闭环：

`多人长对白 → ScriptStructureMap → DirectorUnit/Shot 多对多 → Character/Costume VisualLock → Continuity/J-cut → ImpactEdge → 精准 STALE → Story/Asset 审查`

## 正式对象

- `ScriptStructureMap`：绑定当前 ScriptVersion version/hash；只保存稳定 section/cue 映射、speaker、顺序和文本 hash，不复制剧本文本。
- `ImpactEdge`：保存 source/target 当前引用、dependency scope 和键；身份由 Film Core UUIDv4 生成。
- `STALE`：是目标正式记录 `stale_state` 的独立变化，不改变 review/lock/approval 结论，也不删除旧回执。

## Golden B 必验

1. 至少三名说话角色、长对白 Cue 顺序与文字 hash 可追溯。
2. 两个以上 DirectorUnit 与三个以上 Shot 形成多对多 Coverage，禁止退化为 1:1。
3. 轴线、视线、Blocking、动作/道具接触作为连续性检查；J-cut 只能豁免声音起点差异，不能豁免画面轴线或人物位置漂移。
4. Character Identity 与 Costume 使用 Approved AssetBinding，进入 VisualLockSet 并由 dependency key 精确绑定。
5. 修改一个 Cue 只使依赖该 Cue 的下游对象 STALE；无关 Shot/Prompt/Candidate 保持 fresh。
6. 替换 Costume 只命中对应角色/服装依赖；未声明依赖不得批量 STALE。
7. 任一过期 version/hash、环、非法 scope 或中途失败都必须零部分写入；相同 propagation 重放幂等。
8. Story/Asset UI 默认关闭，关闭态无新增 DOM/请求；开启态仍只做预览或明确 Human 命令。

## 并行边界

- Core/Assets：共享 Schema/OpenAPI、ScriptStructureMap、ImpactEdge、事务传播、审计与查询。
- Story：默认关闭的版本/审查/差异/影响面板，不直接改写 Host 正文。
- Asset UI：Host 资产只读投影、本地媒体 containment、用途绑定与锁状态，不复制/上传媒体。
- QA/Integrator：真实临时 Sidecar Golden B、冲突/恢复、浏览器关闭/开启门禁和总回归。

## 不在本阶段

- 独立 SceneTwin、CameraVersion、BlockingVersion、CompositionVersion 和 Blender/Flova 执行。
- 外部 Dreamina/Comfy/Flova 生成、素材上传、积分消费或 Remote 发布。
- 系统 A/B 正式迁移；只允许只读来源清单与本地 fixture 验证。
- Host Production Canvas 唯一正式创建迁移；继续保持安全预演。
