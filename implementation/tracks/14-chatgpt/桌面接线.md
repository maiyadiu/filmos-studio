## 已实施

- 沿用主线 `Info.plist` 中的 `com.filmos.proposal` / `.filmosproposal` 注册，未重复改写。
- AppKit `AppDelegate.application(_:open:)` 已接收文件打开事件；开关或当前项目上下文缺失时失败关闭。
- `KeychainTokenStore` 使用 Generic Password + `AfterFirstUnlockThisDeviceOnly` 保存 Bridge Session Token 和 Proposal Signing Secret；不同步 iCloud，不写入参数、持久配置或 UI。
- Loopback Bridge 只连接明确的 HTTP loopback root，请求 `/health`，拒绝 redirect；仅在 `ok=true` / `feature=film.chatgpt_app` / `enabled=true` / `public_listener=false` 时标记 `localServiceReady`。
- `/health` 当前是未鉴权的本地身份/开关探针，因此请求明确不携带 Keychain bearer，避免伪本地服务窃取 token。Keychain 检查只证明 token 在本机存在，不证明已鉴权。
- `external_account_connected` 仅作为未验证的 `reportedExternalAccountConnected` 单独记录；`ChatGPTBridgeState.localServiceReady` 只表示本地 loopback 服务可用，不代表 ChatGPT 账号已连接。
- Proposal 文件上限与 Film Core `MAX_PROPOSAL_BYTES` 一致为 1 MiB；拒绝非普通文件、symlink、错误扩展名、换行/空字节路径。
- 原文件先复制到 mode 0600 的受控临时路径；Preview 完成或拒绝后立即删除该副本。
- 不经 shell，只调用锁定的 Film Core 合同：

```text
python -m external_brains.chatgpt.cli preview <controlled.filmosproposal> \
  --project-id <active-project> \
  --state-hash <active-state-hash> \
  --versions-json <active-versions> \
  --receipt-file <controlled-receipt>
```

- Signing Secret 仅在子进程启动时从 Keychain 注入 `FILMOS_CHATGPT_PROPOSAL_SIGNING_SECRET`；命令行没有 secret，没有任意 subcommand 入口。
- Python executable、Film Core app 与 receipt 目录使用规范化的绝对非根路径，调用前重新拒绝 symlink；进程有 20 秒本地超时，stdout/stderr 受 1 MiB 上限约束，临时输出 mode 0600 并删除。
- 只接受 `FILMOS_PROPOSAL_IMPORT_PREVIEW` + `PREVIEW_REQUIRES_HUMAN_APPROVAL` + `formal_write_executed=false`；任何声称已执行正式写入的返回都失败关闭。
- 桌面层不复制签名、过期、project/state/version/content hash、非法命令和幂等规则；这些仍由 Film Core importer 唯一校验。
- Preview UI 不提供 Apply/Approve/Lock 按钮；显示前递归脱敏 secret/token/password/cookie/authorization 字段和本地绝对路径。
