# 第四阶段｜Golden C 与空间版本

## 目标

在第三阶段精准 STALE 之上完成第 15–21 天的本地可重放空间与视频闭环：

`SceneTwin → 3 Cameras → Blocking → Composition → Production Canvas → Previs → Prompt/本地结果 → Video Candidate → Spatial Continuity QC`

## 正式对象与边界

- `SceneTwinVersion`：Film Core 空间真值；绑定坐标系、固定建筑/道具、Portal、WalkableZone、Anchor、CameraZone、ApprovedViewFamily 与渲染 pass 血缘，不复制 Host 通用 Asset。
- `CameraVersion`、`BlockingVersion`、`CompositionVersion`：分别持有机位、表演调度和构图版本；身份由 Core UUIDv4 生成，写入携带当前 version/hash 守卫。
- Production Canvas：继续复用 Host Canvas 与 CanvasUnitLink；正式“取得或创建”必须 Human 显式确认、幂等、校验项目 revision 与 Unit/Script hash，重复历史数据 fail closed。
- Previs、Three.js、Blender 和 Canvas 只产生投影或 Candidate；不得自动写 Approved。
- Video 使用本地 fixture/人工结果验证 Candidate 与空间连续性；不调用外部 Provider。

## Golden C 必验

1. 一个 SceneTwin 至少包含稳定坐标系、固定空间、Portal、WalkableZone、Anchor 与三个 CameraZone。
2. 三个 CameraVersion 分别绑定有效 Anchor/target/lens/axis side，跨轴必须显式声明并进入连续性审查。
3. Blocking 锁定脚、躯干、脸、视线、双手、动作与道具接触链；Composition 独立保存画幅、主体屏幕区与遮挡约束。
4. RGB/Depth/Normal/ObjectID 四类 pass 只保存安全血缘和 hash；ObjectID 缺失不得伪装为通过。
5. Production Canvas 并发重放只得到一个 Canvas；过期 revision/hash 或历史重复均不得产生部分事实。
6. 空间/机位/Blocking/Composition 变化只沿声明依赖精准传播 STALE。
7. Core 重启、SQLite 备份恢复、事务故障和幂等重放后，正式事实、审计和 Stable ID 保持一致。
8. 所有 Stage 4 Feature Flag 默认关闭；关闭后 Host 原项目、章节、Storyboard、Canvas 和资产流程继续可用。

## 并行边界

- Core/Contracts：空间版本、API、迁移、Impact 与恢复。
- Production Canvas：Host service/repository/API 与默认关闭的 Human 创建入口。
- Director/UI：只读空间版本与连续性投影；不拥有正式批准。
- QA/Integrator：Golden C、恢复、浏览器开关矩阵和全量回归。

## 不在本阶段

- Dreamina/Comfy/Flova 的真实外部生成或任务提交。
- Blender R4、Flova Execute 的外部进程执行；只允许本地合同、fixture 与安全 inspect。
- 用户真实数据库迁移、素材上传、积分消费、Remote 发布或 Beta 安装包签名。
- 将 Host Canvas JSON、Three.js 状态或聊天记录提升为正式空间真值。

## 阶段结果

- 状态：`PASSED_LOCAL_INTEGRATION`。
- SceneTwin/Camera/Blocking/Composition 正式版本、组件级精准 STALE、Production Canvas Human 原子创建、Golden C 三镜 Candidate 链、重启/备份/事务恢复和浏览器开关回退均已通过。
- 外部 Provider、Blender/Flova 执行、真实迁移、上传、额度、发布和生产开关仍为 `NOT_AUTHORIZED`。
- 下一阶段：第 22–28 天 Beta 硬化；先锁定范围和验收矩阵，再实施 Remote/Hybrid、Agent Adapter、性能、恢复、迁移、上游兼容与桌面交付的本地安全切片。
